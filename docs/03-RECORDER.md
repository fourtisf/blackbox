# 03: The recorder (`blackbox` CLI + MCP proxy)

Package: `packages/recorder`. Binary name: `blackbox`. npm package name is undecided (see `10-DECISIONS.md`); use `@blackbox-rec/cli` as a placeholder.

## Commands

| Command | What it does |
|---|---|
| `blackbox init` | Detect agent apps, list trading MCP servers found, ask once, back up configs, wrap the servers, add the Blackbox MCP server and skill, create the sealer key, print the `/connect?code=` link |
| `blackbox status` | Agent id, wallet, mode, reveal policy, last seal, queue size, RPC health |
| `blackbox wrap --name <id> -- <cmd...>` | The proxy entry point that `init` writes into MCP configs. Not run by hand |
| `blackbox mode strict\|lenient` | Set enforcement (default `lenient`) |
| `blackbox reveal private\|delayed\|public [--after 24h]` | Set reveal policy (default `delayed`, 24 h) |
| `blackbox ui` | Local replay dashboard on `127.0.0.1` with a one-time token (Milestone 4) |
| `blackbox alerts telegram` | Print a link to connect the Telegram bot |
| `blackbox uninstall` | Restore every backed-up config exactly; keep local records unless `--purge` |

## Agent apps

`init` reads and writes these (Claude Code must **verify the current paths and formats** in each app's docs before implementing):

| App | Where MCP servers are configured |
|---|---|
| Claude Code | user and project MCP config (`claude mcp` CLI writes it); check `~/.claude.json` and `.mcp.json` |
| Codex CLI | `~/.codex/config.toml`, `[mcp_servers.<name>]` |
| OpenClaw | its MCP settings (`openclaw mcp set`) under `~/.openclaw` |
| Hermes Agent | its config under `~/.hermes` |
| Any MCP client | print manual instructions |

Rules for touching configs: back up first to `~/.blackbox/backups/<timestamp>/`, write atomically, read back to verify, never remove the user's own entries, never copy secret values (keep env references as they are).

## How wrapping works

Before:
```json
{ "rushr": { "command": "npx", "args": ["-y", "@rushr/mcp"] } }
```
After:
```json
{ "rushr": { "command": "npx", "args": ["-y", "@blackbox-rec/cli", "wrap", "--name", "rushr", "--", "npx", "-y", "@rushr/mcp"] } }
```

The proxy spawns the real server over stdio (or connects to a remote HTTP MCP URL), passes `tools/list` through unchanged, and intercepts `tools/call`.

It also registers its own MCP server `blackbox` with these tools:

| Tool | Input | Purpose |
|---|---|---|
| `record_decision` | `kind` (buy/sell), `asset`, `intent` {tokenIn, tokenOut, amountIn, maxSlippageBps}, `reasoning`, `context` (object) | Must be called right before any trade |
| `record_pass` | `asset`, `reasoning`, `context` | Called when the agent looks at something and decides not to trade |
| `blackbox_status` | none | Lets the agent see whether recording is healthy |

`init` also installs a short skill / instruction file (Claude Code skill, Codex and OpenClaw instructions) telling the agent: before any trade, call `record_decision` with your reasoning in your own words; when you skip an opportunity you analyzed, call `record_pass`.

## Trade tool detection

A tool call is a trade if:
1. it matches a known server profile (ship profiles for the Robinhood Chain agent kits you can confirm, e.g. swap/trade tools in Rushr, Hedgehood, Oak, QHooks), or
2. its name matches `/(swap|trade|buy|sell|order|open_position|close_position)/i`, or
3. the user listed it in `~/.blackbox/config.json` → `tradeTools`.

Read-only tools (quotes, holders, candles) are logged as tool calls on the next record but never block.

## Per-call flow

```
agent → tools/call swap(...)
  proxy: find the newest record_decision within 120 s whose intent matches the call (same tokens, amount within 1%)
    none found:
      strict  → return MCP error "Call record_decision with your reasoning before trading." (agent retries)
      lenient → create a record with reasoning "" and flag `autoCaptured`, continue
  proxy: build record (seq = next local seq, prev = last leaf), hash, store locally with salt
  proxy: send SealRegistry.seal(agentId, leaf, seq, 1) from the sealer key
  proxy: wait for receipt (poll 150 ms, timeout 2 s)
    success → forward swap to the real server, return its result
    timeout/error:
      strict  → return MCP error "Blackbox could not seal this trade; it was not sent."
      lenient → forward the swap, mark record unsealed, queue the seal for retry (it will land after the trade and be flagged late)
  after result: extract tx hash from the tool result if present → POST /v1/recorder/links {seq, leaf, txHash}
```

Passes and auto-captured tool-call logs go into the batch queue (10 s or 64 records).

## Keys and gas

- Sealer key: secp256k1, generated by `init`, stored in the OS keychain (`keytar`), fallback encrypted file `~/.blackbox/keys/sealer.json` (scrypt + AES-GCM, passphrase prompt).
- The sealer key never holds trading funds. It needs a small ETH balance on Robinhood Chain for gas. Beta default: our relayer sponsors seals (see decisions); build the CLI so either works (`SEAL_MODE=self|relayed`). In relayed mode the CLI signs an EIP-712 `Seal` message and posts it to `POST /v1/recorder/seal`; the relayer submits `sealBySig`.
- The agent wallet's key is never read, copied or stored by Blackbox.

## Local storage

SQLite at `~/.blackbox/agents/<agentId>/records.db`:
- `records(seq PK, ts, kind, json, record_hash, salt, leaf, batch_root, seal_tx, seal_block, trade_tx, revealed_at)`
- `tool_calls(id, ts, server, name, args_json, result_json, args_hash, result_hash, seq_ref)`
- `queue(seq, attempts, next_try_at)`

## Reveal policy

- `private`: only hashes ever leave the machine.
- `delayed` (default): a background task reveals records once `now − ts ≥ after` and the position is closed (for buys) or immediately for passes past the delay.
- `public`: reveal right after sealing.

## Alerts (computed locally, delivered by our bot)

- Loop: the same tool with identical args hash ≥ 10 times in 60 s.
- Spend spike: notional of trades in 5 min > 4× the trailing 7-day 5-min average.
- Silence: no heartbeat for 15 min while the agent was active in the last hour.

The CLI posts `{type, agentId, details}` to `POST /v1/recorder/alerts`; the API sends it through the Telegram bot to linked chats. Heartbeat every 60 s.
